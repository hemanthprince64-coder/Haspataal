## 2. Data Layer — THREE UNCOORDINATED PATIENT IDENTITY STORES (critical)

1. **Canonical Prisma** `packages/db/prisma/schema.prisma:434` → `patients` (the intended source).
2. **Duplicate Prisma** `apps/hospital-hms/prisma/schema.prisma:464` → `patients` via a *second* prisma client (`generator output = "../node_modules/.prisma/client"`).
3. **Supabase** `apps/hospital-hms/supabase/schema.sql:24-38` → `global_patients(mobile unique not null)` + `hospital_patients`. Read at runtime by `apps/hospital-hms/app/api/patient/route.ts:23-33` (decrypts mobile), with the Global↔Hospital mapping flagged "Complex"/unresolved (`patient/route.ts:39-51`).

## 3. Engine-to-Worker Data Flow (as-built)

```
Service mutation → prisma.$transaction([stateChange, outboxEvent.create])   (ONLY in journey/config/settings engines)
        │
        ▼
OutboxEvent (packages/db schema 1413)  ── workers/outbox-relay.worker.ts:68 (SKIP LOCKED, batch)
        │  dispatches by eventType
        ├─▶ workers/timeline.worker.ts:424   → prisma.timelineEvent.create  (SOLE writer)
        ├─▶ workers/rules-worker.ts:30       → RuleExecution (in-memory depthTracker)
        ├─▶ workers/notification.worker.ts   → BulMQ enqueue
        └─▶ workers/search.worker.ts         → search index (in-memory dedup Set)

EventLog (schema 1427) written by services/event-emitter.ts (separate from OutboxEvent).
```

The write pipeline is correct for the **Timeline** engine. It is *not* applied uniformly:
- `apps/hospital-hms/lib/services/ipd.ts` (discharge, admission) uses **Supabase**, no transaction, no Outbox.
- `apps/patient-portal/lib/services.ts:1754` (referral) = bare `prisma.internalReferral.create`, no Outbox.
- `apps/patient-portal/app/actions.ts:2129` builds the longitudinal timeline by **direct Prisma stitching** of `visit/labOrder/patientPrescription/pharmacyDispense` — bypassing the engine.

## 5. Authorization Topology

- `packages/auth/authorization.ts` + `security.ts` = Express middleware, **not imported by any Next.js app** (grep: 0 imports).
- Each app ships its own guard: patient-portal `lib/auth/requireRole.ts` (cookie RBAC), HMS `lib/auth/roleGuard.ts` (JWT), admin-panel raw cookie checks.
- `middleware.ts` exists in hospital-hms but does not centralize engine authorization.

## 7. What Is Structurally Sound (reuse, do NOT rebuild)

- Timeline Engine publisher→Outbox→relay→BullMQ→worker pipeline (`timeline.worker.ts:424` is the only `timelineEvent.create`).
- `EventLog` separation from clinical timeline (`event-emitter.ts:58`).
- Transactional-outbox pattern already proven in `packages/journey/src/engine.ts`, `packages/settings/src/engine.ts:45`, `packages/config/src/engine.ts:87` — use as the reference implementation.
- Escalation worker durable dedup via `@@unique([appointmentId, hospitalId])` + Redis Lua lock (`schema.prisma:1477`, `escalation.worker.ts:44-58`).
- `TimelineSnapshot`, `JourneyTemplateVersion`, `NewbornRecord.babyPatientId` models exist and can be completed rather than rebuilt.
